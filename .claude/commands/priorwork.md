---
description: Search systematically for existing work before claiming novelty — defaults to assuming it's been done
argument-hint: <claim>
---

Before anyone claims novelty for `$ARGUMENTS` (ask if not given), search
for existing work. Default posture: **assume it has already been done,
and make the user prove otherwise** — not the other way around.

1. State precisely what would need to be true for the claim to be novel
   (novel finding? novel method applied to this domain? novel dataset
   combination? these have different bars).
2. Search (web search, not memory) for: academic literature (trade +
   environmental regulation + displacement/leakage — "pollution haven,"
   "regulatory arbitrage," "leakage," specific to pesticides/chemicals
   where possible), NGO/investigative work (this project already
   validates against Unearthed/Public Eye's "Banned in Europe" — check
   what THEY and similar investigations already concluded, not just that
   they exist), and any existing econometric tooling for exactly this
   kind of gravity/PPML displacement estimation (this project already
   found and adopted `pyfixest` — check what else in that space exists
   and whether someone has run this exact design before).
3. Report, for each close match found: how close it actually is (same
   claim? same method, different domain? same domain, weaker method?),
   and what specifically remains unclaimed after accounting for it. "No
   one has done exactly this" is a weak claim if the closest prior work
   differs only in scope, not in kind — say that plainly rather than
   letting a narrow scope difference stand in for novelty.
4. If nothing close is found after a real search (not a cursory one),
   say so, but flag the limits of the search rather than presenting
   absence of evidence as evidence of absence.
5. Give a plain verdict: what, specifically, if anything, is left to
   claim as new, in one or two sentences a skeptical reader would accept.

This command does not modify any file. It answers a question.
